# Whole-program audit — 2026-10-08

Branch `audit-gaps` at cf41813. Method: ruff (bug-prone rule set) over the package, the full test suite,
and a line-by-line read of every module by subsystem, with suspicious behaviour reproduced in the project venv
against synthetic inputs, fake devices or an offscreen Qt session. Nothing in the repo was changed by the audit.
Each finding says VERIFIED (reproduced or traced concretely) or LIKELY (traced, not run).

## Test suite and static analysis

- `pytest tests`: 800 passed, 2 skipped, **1 failed** — `tests/gui/test_apparatus_ui.py::test_ribbon_groups_and_tools`.
  The Apparatus ribbon panel is 1426 px wide (budget 1400). Cause: the "Export map image…" button added to the
  Apparatus group in 5c3e5b9 (only on this branch); the group is now 385 px. Fix: move it next to Import/Export as a
  small button or shorten the label.
- Every process that imports both `cv2` and `av` prints an `objc` duplicate-class warning for `libavdevice`
  (OpenCV 61.x and PyAV 63.x each bundle FFmpeg) — "may cause spurious casting failures and mysterious crashes".
  Relevant because cameras use OpenCV's AVFoundation capture while PyAV is loaded.
- ruff found no real defects beyond cosmetics: unused locals (`anymaze.py:201`, `iomeasures.py:378`,
  `measures.py:600,611`), loop variables bound late in closures (`camsources.py:136,245`, `validate.py:241` — check
  these three capture the intended value), and `QModelIndex()` call defaults (`results/table.py:99,102`,
  `tests.py:96,99`).

## Tracking, video and cameras (core/tracking, video, camera, camsources, camhw, pose, track, geometry, apparatus, templates, occupancy, freezing)

### [HIGH] Adaptive background permanently "ghosts" the animal's starting position
File: manymaze/core/tracking.py:274-277, 387-392 — VERIFIED. First frame becomes the model; foreground pixels are never updated, so an animal present at start leaves a permanent ghost blob the same size as the animal; tracker reported x=60 for 300 frames while the animal was at x=220. Live page uses adaptive whenever there is no empty-arena image (gui/pages/live/single.py:611-613). Fix: absorb static unmatched blobs / always update at a small rate / bootstrap from a median of several frames.

### [HIGH] Identity remembered for one frame only — a single empty frame swaps animals
File: manymaze/core/tracking.py:483-511 — VERIFIED. `_assign` costs only against `self.prev`; after one empty frame two animals came back swapped [220,60]. Fix: keep last-known position + age per identity, gate by max distance.

### [HIGH] Every arena processes the full frame
File: manymaze/core/tracking.py:258-301, 357-395, 619-640 — VERIFIED. `roi` only used for colour tracking; 24 wells on 1280×720 = 55.5 ms/frame vs 2.1 ms single. Fix: crop grey/background/mask to roi, cache blurred/erased background in set_background.

### [MEDIUM] Hidden animal → visible one is k-means split in two
File: manymaze/core/tracking.py:398-432, 377 — VERIFIED. `_single_area` only set for n==1, so split always happens when blobs < n_animals. Fix: learn single-animal area and only split blobs clearly larger.

### [MEDIUM] Changing simulation speed mid-run freezes the reader
File: manymaze/core/camera.py:302-313, 526 — VERIFIED. FramePacer never rebases t_start/index on speed change; produced a 45 s sleep; stop() gives up after 5 s join. Fix: rebase t_start on speed change; sleep in slices checking _stop.

### [MEDIUM] Multi-well plate template: wells vs calibration contradict
File: manymaze/core/templates.py:413-430 — VERIFIED. px_per_cm from 12.78 cm plate, wells spread over the whole box: pitch error 10 % (24-well), 18 % (96-well). Fix: place wells by SBS pitch × px_per_cm.

### [MEDIUM] Unsupported native pixel formats surface as "camera disconnected"
File: manymaze/core/camsources.py:689-695; camhw.py:459-475 — VERIFIED. to_bgr raises for Mono12p/Mono10Packed/RGB12; NativeCamera.read swallows it and returns (False, None); reader reopens for 120 s then reports stall. Fix: surface the conversion error.

### [LOW] Motion/freezing depend on frame_step and fps — tracking.py:619-640, measures.py:170-171 (LIKELY). Normalise by frame interval.
### [LOW] Pose-only recovered animal can persist without limit — tracking.py:570-577 (LIKELY). Cap consecutive pose-only frames.
### [LOW] Several pose jobs share one model but each labelled with its own — tracking.py:705-706, 767-768.
### [LOW] Camera size not re-read after automatic reconnect — camera.py:418, 503-510 (LIKELY).
### [LOW] Two copies of libavdevice loaded (cv2 + av) — objc duplicate-class warning on every run; cameras use OpenCV AVFoundation while PyAV is loaded.
### [LOW] Background window starting past the end of the video clamps to the last frame silently — tracking.py:188-190.
### [IMPROVEMENT] Track.smooth leaves angle unsmoothed (track.py:126-134); occupancy._entry_hysteresis per-frame Python loop (occupancy.py:66-75); y_maze fit height 1.5·arm+1.0·width should be 0.866·width (~1.8 %); demo._wall_walk returns fewer than n frames.

Overall: resources released, NaN handled, colour conversions and geometry correct, playlist frame numbering verified. Weak spots: tracking robustness over time; none covered by tests (adaptive bg with animal present, gaps/occlusion with several animals, FramePacer speed change, multi-well calibration, unsupported pixel formats).

## Outcome (fixes merged into `audit-gaps`)

All findings above were fixed on 2026-10-08, with tests, except the partial items below. Full suite after the merge:
1034 passed, 2 skipped. New test files: `test_audit_measures_stats.py`, `test_procedures_audit.py`,
`test_persistence_fixes.py`, `test_tracking_audit.py`, `test_audit_live_hw.py`, `gui/test_persistence_gui.py`,
`gui/test_shell_audit.py`, `gui/test_audit_gui_live.py`, `gui/test_live_wiring_audit.py`.

Partial or decided differently:
- **Motion vs frame rate:** motion is now independent of the frame step, but it is not rescaled by fps. Rescaling would
  change the stored motion and the freezing thresholds of every existing test.
- **Weigh animal:** other devices and tests are no longer blocked, but the weigh action still pauses its own test's
  frames for up to 3 s.
- **libavdevice duplicate classes:** documented as harmless (`docs/libavdevice-duplicate-classes.md`). The clashing
  classes belong to FFmpeg's camera-input device, which the app never opens.
- **Y-maze fit:** the audit's 0.866·width coefficient was wrong for this geometry; the template now fits
  1.5·arm + 1.183·width.
- **Firmware 1.2:** type-checked with clang against stub Arduino headers, not compiled for AVR or run on a board.
  The New Era safe-mode packet (`safe_mode_s`, off by default) is unverified against the manual.
- **Scheduled re-arm** no longer opens dialogs, so the animal-ID check is skipped and logged for scheduled starts.
- **No GUI relink button:** moved videos are found with `manymaze project DIR relink --folder F`.
- **Blind testing:** results, exports and reports now show treatment codes in the Group column (previously real names).
- **`.mmaze` is no longer a macOS package**, so `exports/` and `recordings/` are visible in Finder.
